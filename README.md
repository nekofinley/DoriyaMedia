# DoriyaMedia

一个用 Go 写的轻量 Emby 替代品:挂载网盘(OpenList / WebDAV / 本地目录)、扫描媒体库、TMDB 刮削,
以及 B 站正版番剧(带弹幕);
并且**针对 iOS Safari 做了播放决策引擎** —— 能直连的一律 302 直连(不占服务器带宽),iOS 播不了的
(MKV / hev1 / EAC3 等)自动转封装成 HLS,视频流直拷、CPU 几乎零消耗。

## 解决什么问题

用 OpenList 挂载天翼云盘时,PC 网页可以直接 302 播放,但 iPhone/iPad 上不行 —— 根因是 iOS
Safari 的解码限制:

| 情况 | iOS Safari 能否直接播 |
| --- | --- |
| MP4 + H.264 + AAC | ✅ 可以 |
| MP4 + HEVC(`hvc1` 标签) + AAC | ✅ 可以(硬解) |
| MP4 + HEVC(`hev1` 标签) | ❌ Safari 要求 `hvc1`,黑屏 |
| MKV(任意编码) | ❌ Safari 根本不支持 MKV 容器 |
| EAC3 / DTS / TrueHD 音轨 | ❌ 有画面没声音 |
| 杜比视界 Profile 5 | ❌ 绿紫色花屏 |

DoriyaMedia 的处理方式:

1. 播放前用 ffprobe(对网盘文件走 HTTP Range 远程探测,结果缓存)拿到容器/编码/编码标签/音轨信息;
2. 结合 UA 识别客户端能力(iOS Safari / Chrome 系 / Firefox);
3. **决策**:
   - 客户端原生支持 + 源可出直链(OpenList/网盘)→ **HTTP 302 直连**,流量不经过服务器;
   - 客户端原生支持但源不可直连(本地目录 / WebDAV)→ **代理播放**(支持 Range);
   - 视频可拷但容器/标签/音轨不兼容 → **HLS 转封装**(`-c:v copy`,只把不兼容音轨转成 AAC),
     iOS Safari 用 AVPlayer 原生播 HLS,HEVC 走硬解;
   - 视频编码本身播不了(RMVB / AV1 / 10bit H.264 等)→ **判为无法播放**并说明原因:
     **服务器不再转码**。实时重编码小机器跟不上,与其让观众对着转圈等一个永远追不上的流,
     不如直接说清这个文件在当前设备上播不了(见下面「关于不转码」)。
4. 播放页可以随时手动覆盖决策(强制直连 / 强制转封装)。

**失败后的兜底链**只在客户端**真的能用**的方案里挑,顺序是 直连 → 代理 → 转封装(便宜到贵),
而且不含转码 —— 它不是"更稳的备用", 而是一个服务器已经不做的承诺。
iOS 上容器是 MKV 的片子不会被兜底到 302 直连(那条路必然播不了)。
播放器这边也会先分清楚"服务端还在生成分片"和"这个模式不对":前者重试同一方案,不急着换。

## 快速开始

```
scripts\build.ps1              # 构建前端 + 嵌入,产出 doriyamedia.exe
.\doriyamedia.exe              # 默认监听 0.0.0.0:5666,数据目录 ./data
```

> 项目从 `Doriya` 改名为 `DoriyaMedia`(模块 `doriyamedia`,二进制 `doriyamedia.exe`)。
> 数据库也改名为 `data/doriyamedia.db`:**首次启动会自动把旧的 `data/doriya.db`(含 WAL 文件)
> 改名过来**,媒体库、扫描结果、账号都原样保留,不需要重扫;`config.json` 文件名不变。

浏览器打开 `http://<服务器IP>:5666`,首次进入会要求创建管理员账号。然后:

1. **设置 → 存储源**:添加 OpenList 源(见下文);
2. **设置 → 媒体库**:选源、填路径(如 `/movies`)、选类型和刮削来源,创建;
3. 点该媒体库的 **扫描**,等状态变为 `done`;
4. 首页出现海报,点进详情 → 播放。用 iPhone Safari 打开同一个地址即可直接播放。

**想让别人也能看?** 默认允许自助注册:把地址给别人,对方在登录页切到「注册」即可,
普通用户共享全部媒体库,但进不了设置后台(见 [多用户](#多用户与注册))。
不想让人随便注册,就到 **设置 → 用户 → 注册与登录** 改成「需要审核」或「关闭注册」。

**不想刮削/不想整理结构?** 直接用顶部导航的 **「文件」**:浏览任意存储源的目录,点视频就播
(同样经过决策引擎:该 302 直连就 302,iOS 播不了的自动转封装,并支持断点续播)。
也可以只建库不填 TMDB key —— 扫描后照样能播,只是没有海报和简介。

环境变量:`DORIYAMEDIA_LOCAL=1` 只监听 127.0.0.1。

## 部署到 Linux(Debian / Ubuntu)

不想在服务器上装 Go 和 Node?直接下预编译包 —— 纯静态、无 CGO 依赖,Release 由
GitHub Actions 自动构建:

| 平台 | 架构 |
| --- | --- |
| linux | amd64 / arm64 / armv7 |
| windows | amd64 |

一键安装(Debian 12/13、Ubuntu 22.04/24.04 及衍生版):

```
curl -fsSL https://raw.githubusercontent.com/nekofinley/DoriyaMedia/main/scripts/install.sh | sudo bash
```

国内网络 `raw.githubusercontent.com` 常常打不开,那就用镜像把脚本取下来(脚本内部还会自动把
下载源回退到镜像,所以只要脚本本身能拉下来就行):

```
curl -fsSL https://ghfast.top/https://raw.githubusercontent.com/nekofinley/DoriyaMedia/main/scripts/install.sh | sudo bash
```

脚本会依次:安装 ffmpeg → 创建系统用户和数据目录 `/var/lib/doriyamedia` → 生成 `config.json`
→ 注册 systemd 服务并启动。下载 Release 时官方不通会**自动按
`官方 → ghfast.top → ghproxy.net → gh-proxy.com` 的顺序回退**,不用手动指定。
升级就是再跑一次同样的命令(自动覆盖二进制并重启);或者装好后直接用下面的 `dm` 命令。

常用选项:

```
# 指定版本
curl -fsSL <上面任一脚本地址> | sudo bash -s -- --version v0.1.0
# 换端口 / 数据目录 / 运行用户
sudo bash install.sh --port 8080 --data-dir /srv/doriyamedia --user media
# 固定用某个镜像源(不走自动回退)
sudo bash install.sh --base-url https://ghfast.top
# 只装不启动
sudo bash install.sh --no-start
# 卸载(--purge 连数据目录一起删)
sudo bash install.sh --uninstall
```

装完的日常操作,直接用安装附带的 **`dm` 管理命令**(类似宝塔的 `bt`,输入 `dm` 回车进菜单):

```
dm                  # 管理菜单:检查更新 / 更新 / 启停 / 日志 / 卸载
dm update           # 更新到最新版(dm update v0.2.1 可指定版本,也能用来降级)
dm check            # 只看看有没有新版本
dm status           # 版本 / 端口 / 运行状态
dm restart          # 启停(start / stop / restart)
dm log              # 跟随日志(Ctrl+C 退出)
dm uninstall        # 卸载(保留数据);dm purge 连数据一起删
```

不用 dm 的话,等价的 systemd 操作:

```
systemctl status doriyamedia
systemctl restart doriyamedia
journalctl -u doriyamedia -f        # 看日志
doriyamedia -version                # 看当前版本
```

也可以在服务器上自己编译(需要 Go 1.26+,`go.mod` 里写的就是 1.26.0;
前端产物 `internal/web/dist` 已随仓库提交,所以**不需要 Node**):

```
CGO_ENABLED=0 go build -ldflags "-s -w" -o doriyamedia ./cmd/doriyamedia
./doriyamedia                       # 前台运行,数据落在 ./data
```

> Linux 上的几个注意点:
> - `data/` 和 `config.json` 都相对**当前工作目录**,systemd 单元里已经设好了 `WorkingDirectory`;
>   手动跑的话记得在自己想要的目录里启动,否则数据会落在奇怪的地方;
> - ffmpeg / ffprobe 按 PATH 查找,也可以在配置里改成绝对路径;
> - **代理默认值是 Windows 上的本地代理**:Bangumi 的 `use_proxy` 默认 `true` 且指向
>   `socks5://127.0.0.1:7890`,在服务器上必然超时 —— 安装脚本会预置成直连。TMDB 默认直连。
>   国内网络两者都需要在 设置 → 刮削与播放 里勾选代理并填自己的地址;
> - 端口 5666 是非特权端口,服务以专用用户 `doriyamedia` 运行,不需要 root。

## 接入 OpenList(天翼云盘)

1. 部署 [OpenList](https://github.com/OpenListTeam/OpenList),添加 **天翼云盘** 存储并填入账号
   (天翼云盘新版需要验证码/设备指纹,按 OpenList 文档操作即可),确认 OpenList 网页里能播放/下载;
2. 在 OpenList 后台 `设置 → 其他` 复制 **令牌(token)**;
3. DoriyaMedia → 设置 → 存储源 → 类型选 `OpenList / AList`:
   - 地址:`http://<openlist主机>:5244`
   - Token:粘贴上面的令牌(不填则要求该路径允许游客访问);
4. 建媒体库 → 扫描。

### 直连(302)的注意点

- 网盘直链一般**绑定出口 IP 和时效**。家里宽带下,服务器和手机走同一个公网出口,302 直连没问题;
  如果手机在外网(流量)、服务器在家,直链可能 403 —— 播放器里点 **强制转封装** 即可
  (转封装模式下由服务器拉流,IP 与取链时一致,总是可用)。
- 若 OpenList 对该存储设置了"代理",`fs/get` 返回的是 OpenList 自己的 `/p` 链接,同样能 302。

### WebDAV 源

WebDAV 源的直链通常需要鉴权头,浏览器拿不到,所以 DoriyaMedia 对 WebDAV 一律走服务器代理
(支持 Range 拖动)。想白嫖 302 直连,请用 OpenList 源。

## 接入 B 站番剧(正版番剧 / PGC)

**「文件」页面里就能看 B 站正版番剧,带弹幕**;也可以把它**建成媒体库**上首页:

```
设置 → 存储源 → 类型选「B站番剧」→ 粘贴账号 Cookie → 添加

只看不建库:文件 → 选这个源 → 点番剧 → 点一集就播
建媒体库  :设置 → 媒体库 → 选这个源 → 路径填 /(或 /热门番剧、/我的追番)→ 类型选剧集 → 扫描
```

虚拟目录树长这样(**剧集按"系列 → 季度 → 集"三层组织**,和 B 站自己的结构一致):

| 路径 | 内容 |
| --- | --- |
| `/` | 平铺的**系列**列表:我的追番 → 正在更新 → 热门(同一系列的多个季度合成一个目录) |
| `/热门番剧` | 按追番人数排的系列 |
| `/我的追番` | 账号追的番(需要 Cookie,没填这个路径会报错) |
| `/<系列> [series <series_id>]` | 这个系列的全部季度 |
| `/<系列>/<季度> [season <season_id>]` | 该季度的每一集,名字形如 `鬼灭之刃 第1话 残酷 [ep267851].mp4` |

**季度会合并成一部剧。** B 站把「鬼灭之刃」「鬼灭之刃 游郭篇」「刀匠村篇」「柱训练篇」
算成同一个系列下的不同季度(`pgc/view/web/season` 返回的 `seasons[]` 就是这张表),
所以进媒体库之后是**一部《鬼灭之刃》+ 10 个季度 + 136 集**,而不是 10 部互不相干的番;
「间谍过家家」同理,季度名直接用 B 站自己的 `第一季 / 第二季 / 第三季`(带中配、粤配),
扫描器把 `第一季` 认成第 1 季、`第二季` 认成第 2 季,季号天然对齐。
季度名是 B 站给的(`游郭篇`、`柱训练篇` 这种篇章名也在内),所以单季的番也有一个季度卡片。

番剧目录名带 `[series <id>]` / `[season <id>]`、每集带 `[ep<id>]`,所以刷新页面、重启
服务之后同一个路径还是同一集(虚拟目录树是**无状态**的);方括号里的标记只用于认路径,
不会出现在界面上。

**为什么是这种形状**:媒体库的扫描器会把**库根目录下的每个目录**当成一部剧,再往下找
"子系列/季度"目录(它本来就支持 `物语系列/{化物语,伪物语}` 这种结构)。所以根目录里
除了系列不能有别的东西 —— 早先版本在根上放了「最近更新 / 10-19」这层结构目录,扫出来
就是一堆叫 `10 21` 的"剧集"、真正的番剧反而被埋掉了。同理,**目录名必须稳定**(只有
标题和 id,没有"更新至12话"这种会变的装饰),否则重扫时会被当成"换了一部剧",旧的
那部连同观看进度一起删掉。

> **建库建议**:媒体库勾上 **Bangumi** 刮削,番剧封面和每集标题就有了(番剧名就是 B 站标题,
> Bangumi 基本都能匹配上);不勾也能扫,只是没有海报。
>
> 花絮 / 声优节目 / PV 这类**额外视频**会出现在「文件」浏览器里但**不进媒体库** ——
> 它们的文件名解析不出集号,扫描器本来就会跳过这一类,不会和正片抢集号。

### 账号 Cookie

留空也能用,但**未登录只有 480P、且会员集只能试看**。填了之后:

| 账号 | 能拿到 |
| --- | --- |
| 未登录 | 360P / 480P,免费集 |
| 登录(普通) | 720P / 1080P |
| 登录 + 大会员 | 1080P 高码率 / 4K,HDR、杜比视界(取决于片源) |

取 Cookie:浏览器登录 bilibili.com → `F12` → **应用 / Application** → **Cookie** →
`https://www.bilibili.com` → 把 `SESSDATA`、`bili_jct`、`buvid3` 几项拼成
`SESSDATA=xxx; bili_jct=xxx; buvid3=xxx` 粘进去(整条复制也行)。

> 这条 Cookie **等同于你的 B 站账号**(含大会员)。它存在 `sources.config` 里,
> 接口只对**管理员**返回,普通用户拿到的是 `******`(见「安全细节」)。

### 扫码登录(推荐)—— 以及为什么粘贴的 Cookie 会「莫名其妙失效」

**从浏览器复制出来的 Cookie 活不长,而且失效时没有任何提示。** B 站网页端会不断
刷新自己的登录态,每刷新一次,之前那一条 `SESSDATA` 就在服务端作废 —— 你复制的那份
只是某一时刻的快照,浏览器下一次刷新它就没用了。`SESSDATA` 字符串里写着 2027 年到期,
**那个日期并不作数**。

失效之后的表现恰好最容易误导人:

| 现象 | 真正的原因 |
| --- | --- |
| 画面变糊,最高只有 480P | 未登录时 `playurl` 只下发 360P/480P,`accept_quality` 里照样写着 4K |
| 会员集提示「需要大会员」/ 只能试看几分钟 | 未登录时会员集返回 `is_preview=1`、没有 DASH 流 —— **和「没开大会员」的返回一模一样** |

所以「我明明有大会员」和「提示要大会员」并不矛盾:请求根本没被认成登录。

**解决办法是在设置页扫码**:存储源卡片上的「扫码登录」用 B 站手机客户端扫一下,
服务器会拿到**属于它自己的**一套会话,外加一个 `refresh_token`。这个会话不会因为
你在浏览器里登录/刷新而被作废,而且可以点「续期」直接换新 Cookie,不用反复扫码。

存储源卡片上还会显示一行账号状态(登录人、大会员到期日,或者「Cookie 已失效」)。
想看详细的就点「重新检查」,它对比两件事:`SESSDATA` 自称的有效期,和 B 站实际怎么回答。

| 状态 | 说明 |
| --- | --- |
| `Cookie 已失效(账号未登录)` | 重新扫码;这一条最常见,尤其是「有效期还没到」的那种 |
| `连不上 bilibili` | 网络/代理问题,**不是** Cookie 问题,先修代理 |
| `已登录 xxx,大会员有效(至 …)` | 正常 |
| `已登录 xxx,大会员已到期` | 会员集要续费;免费集不受影响 |

> 扫码得到的会话也存在 `sources.config`(`bili_refresh_token`),同样是**管理员可见、
> 普通用户掩码**的凭据 —— 它能换出新的 Cookie,泄露的后果和 Cookie 本身一样。

### 服务器在海外:给这个源单独配一个代理

B 站按**请求 IP** 判地区:海外 IP 打开有版权限制的番剧,接口直接返回
`-10403`(「该内容在当前地区不可观看」)。所以「B站番剧」源的表单里多了一个
**代理**字段 —— 给这个源一条自己的出口,和 TMDB / Bangumi 刮削用的代理**互不相干**
(番剧要的是它能看的地区落地 —— 大陆或港澳台,刮削往往要的是另一跳)。

```
设置 → 存储源 → 类型选「B站番剧」→ 代理填 ss://… 或 socks5://… → 测试这个代理
```

**填什么**(四种都行,一个框里粘贴即可):

| 写法 | 说明 |
| --- | --- |
| `ss://aes-256-gcm:密码@host:8388` | **Shadowsocks**(SIP002 分享链接)。加密方式支持 `aes-128-gcm` / `aes-256-gcm` / `chacha20-ietf-poly1305` |
| `ss://` + base64 用户信息 / 整条 base64 / 客户端 JSON | 客户端「复制配置」出来的几种形式都认,节点名(`#香港节点`)会忽略 |
| `socks5://[用户名:密码@]host:1080` | SOCKS5;`socks5h://`、`socks://`、以及裸写的 `host:port` 等价 |
| `http://[用户名:密码@]host:3128` | HTTP 代理(CONNECT) |

> **带插件的节点**(obfs、v2ray-plugin、vmess/trojan/vless 协议)**不在这里解析** ——
> 这类节点请在本机用 Clash / sing-box / v2rayN 跑起来,把它的 **SOCKS5 端口**
> 填进来(`socks5://127.0.0.1:7890`)。插件和 vmess 那套握手不打算在这里重写一遍,
> 但 SOCKS5 这条通用出口对所有客户端都成立。
> 2022 系列加密(`2022-blake3-*`)和老的流加密(`aes-256-cfb`、`rc4-md5`)会**明确报错**,
> 不会静默出错 —— 前者是另一套协议,后者已不安全。

**走代理的范围** —— 这个源的**全部**流量,因为 B 站是按 IP 一票判定的:

- 接口调用(列表、季度、playurl、弹幕);
- CDN 流本身(合流用的 ffmpeg 也走同一条出口);
- 服务端代理播放时的字节(`/api/stream`)。

ffmpeg 只认 `-http_proxy http://…` 这一种代理(实测 8.0.1:给 `socks5://` 会被忽略、
直接裸连 CDN,而裸连正好是被拒的那条路)。所以 SOCKS5 / Shadowsocks 的源会被套一层
**127.0.0.1 上的本地 HTTP 桥**:桥把 CONNECT 转发进真正的代理,ffmpeg 只跟这条本地桥说话。
这样 `ss://` 的节点不需要在机器上另装客户端,也不影响系统里其它进程的代理设置。

**「测试这个代理」按钮**会经这个代理去访问 B 站的地区接口,把**它看到的地区**报给你:

- 中国大陆(`中国 广东 深圳`)→ 正版番剧可以看,绿灯;
- 港澳台(`中国 香港`、`中国 澳门`、`中国 台湾`)→ 能看**港澳台版权**的番剧,
  大陆独家的仍会 `-10403`(绿灯,文案里会说明);
- 海外(`日本 · 东京`)→ 明确提示「大部分正版番剧会报地区限制」,红灯。

「测试连接」在带代理时也会顺带跑一次这个检查,所以点一次就知道**连通**和**地区**两件事。
没有配代理时它就跑本机出口 —— 一个海外机器上直接点一下,能看到自己为什么会 `-10403`。

> 代理串里带密码(Shadowsocks 的密码就是密钥),所以它和 Cookie 一样:
> 只对管理员返回明文,普通用户拿到的是 `ss://aes-256-gcm:******@host:8388`。

### 港澳台代理:只上架当前线路能看的番剧

B 站的番剧版权按地区分开:大陆和港澳台是两套片库。代理落地在香港,能看
**港澳台限定**的番剧,但**大陆独家**的会回 `-10403`;反过来也一样。所以「落地大陆」
不是唯一正确的答案,取决于你想看哪一边。

源表单里因此有一个 **「只上架当前线路能播放的番剧」** 开关(新建源默认打开):

- 扫描媒体库时,每个季度目录会多问一次 `playurl`;当前地区回 `-10403` 的季度按
  **空目录**处理 —— 不进媒体库,重扫时也会把之前扫描留下的条目一起清掉;
- 港澳台代理能播的季度照常上架,所以「港澳台限定」的番会留下,「大陆限定」的会被跳过;
- **只有明确的 `-10403` 才会跳过**;超时、风控、账号问题都当作「照常上架」,
  不会因为一次网络抖动把库删空;
- 判定按 **(季度, 代理)** 缓存 6 小时,重扫和翻页不会反复请求;改了代理字符串会立即重新判定;
- 它作用于这个源的**所有列表**,所以文件浏览器里也看不到被跳过季度的剧集 —— 那些本来也播不了;
- 关掉这个开关就回到旧行为:列表里有什么就上架什么,播不了时在播放页报 `-10403`。

> 代理在港澳台时建议保持开启;代理在大陆时开不开差别不大(大陆版权的番都能看)。

### 繁体标题也能刮削到

港澳台片库的番剧名是繁体(`鬼滅之刃`、`間諜家家酒`、`葬送的芙莉蓮`),而 TMDB / Bangumi
的中文名是简体;直接拿繁体去搜,经常一条都搜不到,或者搜到的是别的番。现在搜索和比对
都会先把标题折叠成简体(OpenCC t2s,**只用于匹配,不改写入库的原始标题**):

- Bangumi:先按原标题搜,没有再按简体搜;换写法搜到的结果仍按原标题打分,不会乱配;
- TMDB:两种写法都试,并在结果里挑和标题最像的一条(年份参与打分),不再盲取第一条;
- 匹配成功后,条目名会换成刮削源的中文名(通常是简体),`original_title` 保留原名。

> 转换只影响「找条目」这一步。没有匹配到刮削条目时,库里的标题仍是 B 站给的那一版。

### B 站角标

来自 B 站源的剧集,在**海报、剧集缩略图、季度卡、播放器选集侧栏**的右上角会带一个蓝色
`bilibili` 小角标(小电视图形)。它读的是扫描写进 `items.source_type` 的来源类型:

- 一个条目的**全部文件**都来自同一种源时才标记;混了本地/网盘版本的条目不标,避免标错;
- 老库升级后会自动补一次,不需要重扫;之后每次扫描结束都会重算,源被删掉/换掉也会跟着变。


### 为什么不能像网盘那样 302 直连,或者只代理不封装

这是最常被问到的一点(「B 站本来就给多种封装和编码,应该所有设备都能直接播吧」),
所以把实测数据放在这里 —— 每一行都是在装了 DoriyaMedia 的这台机器上跑出来的:

| 取到的 URL | 不带 Referer | `Referer: bilibili.com` | `Referer: 本站地址` |
| --- | --- | --- | --- |
| 番剧 DASH 视频流(3 个 host 各测) | **403** | 206 | **403** |
| 番剧 DASH 音频流 | **403** | 206 | **403** |
| 番剧单文件 MP4(`platform=html5`) | **403** | 206 | **403** |
| 普通投稿(UGC)单文件 MP4 | **206** | 206 | 206 |

结论分三层:

1. **番剧(PGC)的 302 直连是死的**。CDN 要 `Referer: https://www.bilibili.com/`,
   而浏览器的 Referer 只会是本站地址(服务端无法指定,`Referrer-Policy` 只能减少不能改写),
   所以浏览器自己去拉一定是 403。上表里番剧的三种 URL、每一台 CDN 都是这个结果。
2. **"官方已封装好的单文件"确实存在,而且能只代理不封装**:番剧接口换成
   `platform=html5` 会返回**一个音视频在一起的 MP4**(实测 61MB / 整集 1425 秒),
   服务器只要转发字节(带 Range 拖动),**不解码、不封装、不落盘,CPU 零消耗**。
   代价是清晰度:B 站这条老通道只给 360P(未登录实测 `quality=16`,
   同一集 DASH 通道能给到 1080P+;登录后这条通道历史上封顶 720P)。
   DoriyaMedia 目前**没有走这条路**,因为番剧的价值在 1080P 及以上,而这条通道给不了。
3. **UGC 的单文件链接有时能裸拉**(上表最后一行),但**不可依赖** —— 同一台 CDN 上,
   番剧的 URL 就是 403。要利用它只能"取链后先试一次"再决定 302 还是代理。

所以现在的取舍是:**番剧走服务端合流换清晰度**(`-c:v copy`,不重编码,只是搬运+改封装),
CPU 开销接近零,代价是一集的 HLS 缓存会落在磁盘上(480P 约 90MB/集,按 `hls_cache_mb` 淘汰)。
如果你更在意"服务器一点都不参与",可以用 `platform=html5` 的单文件 + 代理模式换 360P/720P
—— 这条路已经验证过可行,只是还没做进产品里。

**清晰度在播放器里调。** 旧版本在存储源上有一个「清晰度上限」,存进去就固定了整库的播放,
想换只能改设置再重开一集;现在这个设置已经删掉。每集第一次播放默认取账号能给的最高一档
(SDR 优先,HEVC / HDR 不会被误选),播放器控制栏的「清晰度」按钮给出这集**真正能播的整副梯子**
(不是 B 站接口里那些没买的 4K/HDR),点一下就能在播放中换档。

换档在服务端是一次新的封装任务:番剧的画面和声音分别 seek 会落到不同位置(实测请求第 8 秒,
画面在 6.2s、声音在 9.4s,播放器直接报 `Parsed buffers not in DTS sequence`),所以新的一档
仍然从 0 开始封装。播放器会先让这一档封装到结尾(播放列表拿到 `#EXT-X-ENDLIST`,才能像点播
一样准确 seek),再跳到当前位置接着播;等待期间显示「已生成 X / 目标 Y」和「正在重新封装…」。
封装是 `-c:v copy`,通常几秒到几十秒。写进播放地址的 `q=` 会把这次播放钉在那一档上,
同一集的另一次换档因此不会被旧档的分片串进来。


B 站的流和其它源不是一个形状,这也是它不能靠 `.strm` 或 OpenList 中转的原因:

1. **CDN 校验 Referer**:不带 `Referer: https://www.bilibili.com/` 一律 `403`,
   所以浏览器拿不到直链、**302 直连在这里是不可能的**,流量必然过服务器;
2. **音视频是两条流**(DASH):画面和声音在两个 URL 上,单独播任何一条都是"有画没声";
3. 直链带 `deadline`,**约 2 小时过期**,所以每次播放都重新取链(引擎的解析缓存 10 分钟)。

所以决策引擎里这类源只有一个选项:**服务端用 ffmpeg 把两条流合起来**(`-c:v copy`,
不重编码),打包成 fMP4 HLS 由播放器拉取。实测 24 分钟一集、480P,整集转封装约 8 秒,
远快于播放速度,所以拖动进度条也是即时的。

打包用的是**长驻会话**(和 HEVC 转 Apple 时同一条路):一次播放只开**一个** ffmpeg、
只连一次 CDN,而不是每 4 秒重开一次 —— 逐片重开在这类源上不只是慢,两条流各自 seek
会落到不同位置(请求第 8 秒,画面落在 6.2s、声音落在 9.4s),播放器会以
`Parsed buffers not in DTS sequence` 直接拒播。

**只发写完的文件。** ffmpeg 默认**原地写** `index.m3u8`、`init.mp4`、`segNNNNN.m4s`,
而文件"存在"不等于"写完" —— 实测一个分片曾以 **0 字节出现在最终文件名下、再长到 14MB**。
播放器在那瞬间取到的是半截 fMP4,和真正的解码失败无法区分:它报 media error 并且**不再重试
这个分片**,用户看到失败卡片,手动重试却又能播(那时文件已经写完)。

现在三层都堵上了:

- 分片交给 ffmpeg 的 `-hls_flags temp_file`:先写 `<name>.tmp`,写完才改名,所以出现在
  最终名字下的分片一定是完整的;
- **播放列表**是原地重写的(这个标志管不到它),所以服务端等到它"以换行结尾、且带着
  `#EXTM3U`"才发出去 —— 半截的播放列表解析不了,播放器会当成致命错误;
- **init 分片**也是原地写(`temp_file` 同样不覆盖它),所以等到它的大小连续两次采样不变
  才发出去。

顺带:采纳上次运行残留的缓存时,改成校验**播放列表点名的每个分片都真的存在**(被杀掉的
ffmpeg 会留下一个列表里已列出、文件却没写完的分片),否则会把播放器指向一个永远不会产生
的分片。这些等待对**已经写完**的会话是零开销(实测 60ms 内返回)。

逐片那条路(没有长驻会话时)同样是"生产完才发":ffmpeg 中途失败时客户端一个字节都收不到,
于是服务端能诚实地回 502(播放器会重试这个分片),而不是发一份截断的数据让它以为是解码
失败。

**长驻会话也要会"说话"。** 逐片那条路每生成一段都会记一笔进度(`/api/play/{id}/status`
里的 `stream`),而长驻会话一次 ffmpeg 到底,这些计数**一个都不动** —— 于是播放器问"服务端
还在干活吗"时被告知什么都没有,只好用自己的超时判断,把一个只是**起得慢**的流判成"这个
模式不行"。冷启动的 4K 云盘文件正好是这种情况:第一段要解析链接、穿透冷存储、拉几十 MB,
远超任何固定超时。现在状态接口直接读会话自己的产出(播放列表里的 `#EXTINF` 条数与总时长、
最近一次变化时间),并给出 `packager_running` —— 打包器还活着就是还在干活,播放器据此
继续等,而不是弹失败卡片。

**被打包器拒绝的链接会当场换一条重试。** 冷文件第一次播放会解析**两次**链接(一次给探测,
一次给打包),而云盘常常在签发新链接时作废上一个 —— 打包器可能拿着刚被拒的链接启动、立刻
死掉。逐片那条路一直有"换新链接重试"(见 `Engine.Segment`),长驻会话这条**没有**:于是
第一次播放失败、用户点一下重试(那次会重新解析链接)就好了。现在这条也补上了,在同一个请求
里换新链接重试一次(`RetryWithFreshLink`);第二次仍失败才把错误交出去。

失败时错误卡片会带上**服务端自己的说法**(502 的正文),而不是只有一句"解码或网络错误"。

### 弹幕

每条弹幕(1-3 滚动 / 4 底部 / 5 顶部 / 6 逆向)由服务端 `/api/danmaku/{fileId}/comments.json`
一次取回(通常几千条),播放器用一块画布画在画面上:

- 弹幕层**不吃触摸事件**(`pointer-events:none`),点画面、拖进度、全屏都不受影响;
- 位置是播放时间的纯函数,所以**拖动进度条之后弹幕依然对得上**;
- 这一集没有弹幕时,控制项自己消失(只有 B 站源有弹幕)。

画面下方的控制条上有**两个**按钮,和 B 站一样:**开关**负责开关(按 `D` 也行,切换时会提示一句),
**设置**负责调参数。开关不顺手去翻抽屉 —— 看剧时随手开关是常态,调参数是一次性的事;
设置也不是抽屉的一部分,它是自己的一小块面板,从按钮上方展开(手机/平板这种图片下面还有
整页的布局则从按钮下方展开,免得盖住画面)。

「弹幕设置」和 B 站自己的一致,另外多一个描边开关,选择记在浏览器里:

| 项 | 取值 | 默认 |
| --- | --- | --- |
| 显示区域 | `1/4 屏` / `半屏` / `3/4 屏` / `全屏` | 半屏 |
| 不透明度 | 0–100% | 90% |
| 字号 | `极小` / `小` / `中` / `大` / `极大` | 中 |
| 速度 | 滑块,`慢` ←→ `快`(右端最快,4 秒穿过屏幕) | 8 秒 |
| 弹幕类型 | `滚动` / `顶部` / `底部` 各自开关 | 全开 |
| 字体黑边 | 开关,关掉后文字不再描黑边 | 开启 |
| 恢复默认 | 一键还原上面六项 | — |

第一条弹幕**不与画面顶边齐平**:每条轨道都从字号的一个小间距之下起笔(字号越大留白越大),
字顶和描边不会在画面最上沿被切掉。

「字体黑边」关掉后文字直接压在画面上;默认开启,因为浅色字叠在亮画面上时黑边是主要的
对比度来源。这一项和别的设置一样只重画画布,不会重新请求弹幕。

被关掉的类型**连跑道都不占**(不是画上去再隐藏),所以关掉顶部不会在画面中间留一排空档;
`1/4 屏` 会把底部弹幕也压在上四分之一里,而不是钉在画面底部。

关掉开关只是把图层收起来,**取回过的弹幕留在内存里**,再打开立刻就有,不用重新请求、也不用刷新。

### 边界与注意

- **只做正版番剧(PGC)**:普通投稿视频、直播、互动视频不在这个源里;
- **会员集没有大会员就是看不了**,服务端会明确告诉你「这一集需要大会员」,
  而不是黑屏或转圈 —— 这类集 B 站返回的是 `is_preview=1` 且没有 DASH 字段,
  不是错误码,必须显式识别;
- 部分番剧有**地区限制**,当前 IP 看不到的会报「该内容在当前地区不可观看(-10403)」;
  服务器在海外时,给这个源配一个中国大陆落地的代理即可(见上面「服务器在海外」一节),
  代理会连 CDN 流一起接管;
- 转封装会在**磁盘上留一份该集的 HLS 缓存**(480P 约 90MB/集,1080P 更大),
  由 `hls_cache_mb`(默认 2GB)按最近使用淘汰,播完的集下次播放直接命中缓存;
- 请求别太密:风控(`-352`)会拦,表现是番剧列表变空。驱动的列表/详情有 10-30 分钟缓存,
  正常情况下一次翻页只打一次接口;
- **扫描是限速的**:接口调用之间强制间隔 150ms(扫描并发 4 也照样排队),所以一次扫
  60~100 部番剧要十几秒 —— 换来的是不会因为一次扫描把风控招来(列表被拦空 = 库被删);
- 仅供自己/家人观看,不要再分发 —— B 站服务条款不允许抓取与再分发。

### 自己验证一遍

`scripts/bilibili-live-test.ps1` 会另起一个临时实例(自己的端口和数据目录,不碰你的数据),
把整条链路走一遍:浏览季度 → 注册一集 → 播放决策 → 拉播放列表和分片 → 用 ffprobe 确认
**分片同时含视频和音频、且相邻分片时间戳不重叠** → 取弹幕 → 确认会员集被明确拒绝 →
**建一个剧集库并扫描,确认「鬼灭之刃」在库里只有一部、下面挂着 10 个季度、季度里有剧集**。

可以反复跑:实例已经在跑就复用并登录,上一轮留下的库和源会先清掉,所以数量断言不会
被旧数据干扰。端口按 `-Port` 分开(`.tmp\bili-e2e-<端口>`),两份可以同时跑。

```
pwsh scripts/bilibili-live-test.ps1                      # 不登录,免费集

```

**读画布像素**确认弹幕真的画出来了(而不是只有一块空画布),再确认关掉开关后画布被隐藏、
开回来时立刻又画出来。「字体黑边」开关还单独比对暂停帧里的深色像素:关掉后描边消失、白字还在,

(自己的端口和数据目录,不碰你的数据),自己找一集带弹幕的,然后逐条确认 —— 两个按钮确实在
进度条下方那一行、**播放设置抽屉里已经没有弹幕那一段**、面板各项和默认值都在、面板里的选择
落进了 localStorage、开关只收放图层不动播放、手机布局下面板向下展开而不是盖住画面。

选集与顶栏也有一份(`.uitest/check-player-episodes.mjs`):它用 `testdata` 的测试剧集扫出一个
真实的两集季,在 headless Chrome 里打开第 1 集 —— 确认顶栏只剩「返回」、选集按钮就在字幕按钮
左边、面板列出整季且标出当前集,点第 2 集之后**地址、标题、播放**三样都跟着换了。
它还确认了齿轮菜单里的「全部播放设置」能把抽屉叫出来,顶栏那颗旧按钮去掉后并没有把
版本/音轨的入口一起带走。

## 媒体库可以挂多个存储源

一个媒体库能同时扫多个地方 —— 同一部剧拆在两个网盘、番剧在云端而字幕在某台机器上,
都可以放进同一个库:

```
设置 → 媒体库 → 展开表单 → 存储源与路径:选一个源填一个路径 → 「再加一个源」
扫描时会把它们一起扫,合并成同一批剧集与电影(同一部剧出现在两个源也能归到一部)
```

- **文件按"来源 + 路径"认身份**:同一个路径出现在两个源里是两个不同的文件,不会互相顶掉;
- **移除某个源之后重扫,只删它自己的条目**,库里其它源的剧和观看进度不受影响;
- **某个源这次没读到(网络失败、盘没挂上),它的条目会被原样保留** —— 读不出来不等于文件没了。
  扫描日志里会明确写出「部分源读取失败(不清理这些源)」;
- 删掉一个**源**时,只要这个库还挂着别的源,库本身会留着(它的"首个源"自动换成剩下的那个);
- 剧集级的本地 nfo/海报按**文件所在的那个源**去找,不再假定库的首个源。

## 剧集识别与季/版本结构

扫描按 **剧名 → 季 → 集** 归组,目录怎么套都能认:

- 季目录:`第 1 季` / `第2季` / `第二季` / `Season 1` / `S01` / 纯数字(`1`、`0`);
- 版本目录不参与剧名:`bdrip` / `webrip` / `1080p` / `x265` / 压制组目录…… 会被跳过,
  所以 `剧名/bdrip/第 1 季/…` 和 `剧名/第 1 季/webrip/…` 都归到同一个剧的同一季;
- **特别篇独立成季**:`OAD` / `OVA` / `剧场版` / `SP` / `特典` / `番外` / `总集篇` 各自一张季卡片,
  不会再出现"剧名就叫 OAD / bdrip"的情况;
- **子系列 / 篇章目录算"命名季"**:`物语系列/{化物语,伪物语}`、`青之驱魔师/{岛根启明结社篇,京都不淨王篇}`、
  `刀剑神域/{Alicization篇,…}` 这类"父目录下挂着好几部子系列"的结构,会把**父目录当剧名**、
  每个子目录当一季(季卡片直接显示 `化物语` / `岛根启明结社篇`),不会再分裂成好几部同名剧;
  命名季的季号是自动分配的,不会和 `第 1 季` 抢号;
- **分类目录与字幕目录不会变成剧名**:`Movie` / `Anime` / `合集` / `未分类` 这类归类目录,
  以及 `简体` / `CHS` / `Big5` 这类语言目录都会被跳过(`/Cartoon/Movie/你的名字/…` 的剧名是 `你的名字`);
- **同一集的多版本会自动合并**:同一季里 bdrip 与 webrip 的同编号文件落进同一集,
  剧集页先选季 → 季页面每集右侧选 `BDRip · HEVC 10bit · 1080p` / `WebRip · AVC · 1080p` 再播,
  播放页底部也能随时切版本;**单版本剧集**同样有播放按钮(接口对每集都会给出可播文件);
- **只有正片才算"同一个第 N 集"**:bilibili 把 `PV` / `预告` / `特别篇` / `花絮` 放在和正片并列的
  **section** 里,而且名字就写成观众说法(`第3话预告` 是第 3 话的预告)。这类条目由源自己在文件名里
  标出所属 section(`[sp#11#PV&其他]`),扫描读这个标记而不是读名字,所以它们各自成一张季卡片
  (卡片名就是 bilibili 的 section 名),不会被当成"第 3 集的另一个版本"——以前点开会播到几十秒的预告片;
- **剧集名优先用源自己的命名**:bilibili 的条目名(如 `第3话 新国王`、`PV&其他 第3话预告 新国王`)
  在扫描时就写进剧集名,元数据刮削只补剧照/播出日期,不再按集号猜标题(按集号猜正是第二季套上
  第一季分集名的原因);
- 重扫会**重新归组**已有文件(文件行按源+路径唯一),改了解析规则不需要删库重建;
  重扫后空的旧剧/旧季会被自动清理,重复条目(如两个"物语系列")合并成一个。

## 字幕体检(找出缺字幕的剧集)

「这季到底有没有字幕」在播放之前是看不出来的:扫描只登记视频文件,字幕是**打开某一集时**
才去同目录找。所以一季可能看起来整齐,点开才发现没字幕。

**设置 → 媒体库 →「查缺字幕」** 就是回答这个问题(每个媒体库一个按钮)。结果按**剧集聚合**,
点标题进详情页、点季号进季页面,一眼看出该补哪几部。

**只查 bdrip。** WebRip 的片子通常把字幕**烧进画面**了 —— 既没有字幕文件、也没有字幕轨可查,
工具分辨不出"有烧录"和"什么都没有",报成缺字幕十有八九是错的。所以版本目录里带
`bdrip` / `blu-ray` / `bdmv` 之类的才算数,webrip 会被跳过并在结果里显示跳过了多少个。

判定分两级,因为两半答案的代价差很多:

| 阶段 | 手段 | 代价 | 覆盖 |
| --- | --- | --- | --- |
| ① 外挂字幕 | 列出所在目录,和视频名做配对 | 每个目录一次列目录(毫秒级) | 绝大多数 —— 这类发布都把字幕当外挂文件发 |
| ② 内嵌字幕 | 对没被 ① 排除的文件跑一次 ffprobe | 网盘文件每个几秒到几十秒,**后台**进行 | 剩下那些没外挂字幕的 |

所以**几十秒就能拿到可用的名单**,然后后台慢慢把内嵌字幕的那几个划掉。还没确认完的条目
显示为 `?`(虚线),确认没有的显示为 `!`(探测失败,还没定论) —— 名单不会把没查实的说成"缺"。

顺带一个好处:阶段 ① 找到的字幕会像播放时那样登记进库,所以体检完再点开那些剧集,
字幕是现成的。

**目录读不出来就不算缺**(记在「N 个无法判断」里):源上已删除或无权限的目录,报成缺字幕
是把"没查"说成"没有"。

结果界面里:

- `N 个 bdrip 文件` / `有外挂字幕` / `有内嵌字幕` / `缺字幕` / `跳过 N 个非 bdrip` / `N 个无法判断`;
- 按剧聚合,展开后是每个季的集号 chip,点进去就能看;
- 体检进行中可以 **停止体检**,已查到的结果保留;重跑会覆盖上一次的结果。

实测一个 1455 个 bdrip 文件的库:① 阶段 48 秒出结果(1293 个有外挂字幕,17 个待确认),
② 阶段把这 17 个探完,内嵌字幕 0 个,最终 29 集确认缺字幕。

## 刮削

- 来源按优先级:**本地 nfo/海报 → TMDB**(每个媒体库可配置,勾选即启用);
- 本地 nfo 支持 Kodi 格式:`movie.nfo` / `tvshow.nfo` / `*.nfo`、`poster.jpg`、`fanart.jpg` 等
  (支持网盘目录里直接读取);
- TMDB 需要在 设置 → 刮削与播放 里填 API Key(免费,v3 密钥与 v4 读访问令牌都支持);
- 国内网络两种走法:**① 勾选「走本地代理访问 TMDB」**并填代理地址(默认 `socks5://127.0.0.1:7890`,
  也支持 `http://`),TMDB 接口与海报/背景图下载都会走这个代理;② 把 API/图片地址改成镜像或自建反代。
  设置页有 **测试连接** 按钮,会实时区分「代理没启动 / 超时被墙 / Key 无效」;
- 详情页可对单个条目 **重新识别**;番剧名有歧义时,在详情页填 **Bangumi ID** 点「按 ID 匹配」即可钉住某一部。

### Bangumi(bgm.tv)—— 番剧中文数据

番剧库建议勾上 **Bangumi** 这个刮削来源,它补齐 TMDB 的短板:

- **中文剧名**(原名进 `original_title`,如「孤独摇滚！」/「ぼっち・ざ・ろっく！」);
- **每集中文标题 + 播出日期**(如「第 1 集 翻转孤独 · 2022-10-08」);
- 评分、标签(芳文社 / 音乐 / 轻百合…)、封面。

配置在 设置 → 刮削与播放 → **Bangumi 刮削**:令牌可留空(公开接口够用),
**网络代理默认开启** —— `api.bgm.tv` 在不少网络下会被 DNS 污染(解析到无关 IP 后超时),
走本地代理即正常;有 **测试连接** 按钮,会返回中文/日文搜索结果,一眼看出是网络问题还是没这个条目。

**名字和条目差一两个字也能认**:下载/网盘目录常多一个或少一个字——比如「别再当欧尼酱了！」其实是
《别当欧尼酱了！》,「监狱学院」其实是《监狱学园》。精确匹配失败时会自动去掉一个字换一种拼写再搜一次,
并且**始终按原标题做相似度校验**;搜索结果第一条如果跟标题不像,不会硬套(对「别再当欧尼酱了！」直接搜,
bgm 的第一条是《凡人修仙传 年番》,那种结果会被拒绝)。实在认不出来就保持空白,在详情页按 **Bangumi ID** 钉住即可。

### 搜「还没入库」的番剧(B 站源)

搜索框(⌘/Ctrl + K)除了搜媒体库,也会用挂了 B 站源的剧集库去搜 **B 站片库**。库里还没有的条目
显示在「B 站片库 · 未入库」那一行:点一张卡,只把这一个系列读进来,同时打开一个实时加载页,
依次显示「读取季度与剧集 → 建立剧集条目 → 匹配封面与简介」,完成后自动跳到详情页。

- 导入的是**整个系列**(同一系列的所有季度一起读),和正常扫码得到的目录结构一致,之后再扫也不会重复；
- 只走**这一个系列的子树**,不遍历整个片库；清理也只清理这次真正读过的目录,库里其它番剧不受影响；
- 片库搜索有 10 分钟缓存,并自动补上 B 站风控要求的 `buvid3`；输入不足两个字不会发请求；
- 被 B 站限流时,「B 站片库」那一行会直接提示,过几分钟再试即可。

## 多用户与注册

一台服务器上可以有很多账号,默认**开放注册**。

### 角色与边界

| 角色 | 能做什么 |
| --- | --- |
| **管理员** `admin` | 全部功能:设置后台(存储源、媒体库、刮削、用户)、扫描、浏览播放 |
| **普通用户** `user` | 浏览、搜索、播放、自己账号的改名改密;**进不了设置后台** |

普通用户**共享全部媒体库**(不按库分权),播放进度按账号各自记录,互不影响。

「后台只有管理员能进」在三层同时生效:

1. **API**:`/api/config`、`/api/sources`、`/api/libraries` 的写操作、`/api/admin/*`
   全部走 `requireAdmin`,非管理员一律 `403 需要管理员权限`;
2. **路由**:前端 `/settings` 带 `meta.admin`,普通用户访问会跳回首页并提示「需要管理员权限」;
3. **入口**:桌面端账号菜单与手机端底部导航对普通用户不显示「设置」。

### 注册的三种模式(设置 → 用户)

| 模式 | 行为 |
| --- | --- |
| **开放注册**(默认) | 登录页出现「注册」页签,注册完立即登录可用 |
| **需要审核** | 注册后账号为 `待审核`,登录会被拒;管理员在设置 → 用户点「通过」才生效 |
| **关闭注册** | 登录页不再显示注册页签;只能由管理员在设置里手动建号 |

同一张卡片里还能设 **密码最短长度**(默认 4,注册 / 建号 / 改密都按它校验)。改完点保存即时生效,
不需要重启。

### 管理员的用户管理(设置 → 用户)

- **用户列表**:角色、状态、创建时间、**上次登录**,当前登录的账号会标出来;
- **添加用户**:直接建号并指定角色(注册关闭时也能用);
- **通过 / 拒绝**:审核模式下的待审核注册单独成区,一眼看到有几个人在等;
- **设为管理员 / 降为用户**:给家人开后台权限,或收回来;
- **禁用 / 启用**:禁用后**已登录的会话立即失效**(不是等他下次登录),播放记录保留;
- **重置密码**:管理员代设新密码(明文显示便于转告),该账号其他设备会被下线;
- **踢下线**:只结束该账号所有设备的登录,不动账号本身;
- **删除**:连带删除该账号的会话与播放记录。

**防呆规则**(服务端与界面同时生效):

- 不能禁用、删除**当前登录的自己**;
- **至少要保留一个可用的管理员**:只剩一个管理员时,不能把他降级 / 禁用 / 删除;
  想卸任,先给另一个人开管理员权限,再降自己;
- 用户名**不区分大小写**:已有 `admin` 时,注册 `Admin` 会被拒,避免出现看着一样的仿冒账号;
- 服务**首次初始化之前**不接受注册,避免陌生人抢在主人之前注册、把初始化流程堵死。

### 账号自助(右上角头像 → 账号设置)

每个用户都能改名、改自己的密码(需要验证当前密码)。改密后**只有当前设备保持登录**,
其他设备需要重新登录 —— 密码泄露时这就是一键止损。

### 安全细节

- 密码用 **PBKDF2-SHA256**(6 万次迭代 + 每账号随机盐)存储,接口从不返回 hash;
- 会话是随机 token,写进 `HttpOnly` Cookie,默认 **30 天**有效;过期的会话会在下次登录时清理;
- **登录限流**:同一 IP 5 分钟内错 10 次就 `429`,密码正确也要等窗口过去 —— 开放注册后
  登录页谁都能访问,不能让人无限猜;
- **注册限流**:同一 IP 每小时最多 5 次自助注册,防止脚本刷满用户表(管理员手动建号不受限);
- 限流按 **TCP 来源地址** 计,故意不信任 `X-Forwarded-For`(那个头客户端可以自己伪造)。
  挂在反向代理后面时,所有人会共用代理的地址,此时限流按整体计算;
- **存储源的凭据只给管理员看**:`GET /api/sources` 对所有登录用户开放(文件页要列源),
  所以 WebDAV 密码、OpenList 令牌和 B 站 Cookie 在返回给普通用户时被替换成 `******`
  —— 一条 B 站 Cookie 等于一整个账号(含大会员),不能跟着源列表一起发出去。

> 老版本的单账号数据库**无需迁移操作**:首次启动会自动给 `users` 表补上 `status` /
> `last_login_at` 两列,原管理员账号保持管理员身份、可直接登录,媒体库与播放记录不受影响。

## 邮件与人机验证

两件事一起配:**邮箱验证**(证明注册的人真的拥有那个邮箱)和 **Cloudflare Turnstile**
(挡脚本)。都在 **设置 → 邮件与验证** 里,改完即时生效,不用重启。

### 1. 先配 SMTP

| 项 | 说明 |
| --- | --- |
| SMTP 服务器 / 端口 | 表单上有 **QQ 邮箱 / 163 / Gmail / Outlook** 四个快捷按钮,点一下自动填好 |
| 用户名 | 一般是完整邮箱地址 |
| 密码 / 授权码 | **不是网页登录密码**,而是邮箱设置里生成的「授权码 / 应用专用密码」 |
| 发件人地址 | 留空就用用户名。大多数服务商要求发件人和登录账号一致 |
| 加密方式 | `STARTTLS`(587,默认)/ `隐式 TLS`(465)/ `不加密`(仅本机中继) |
| 发送走代理 | 留空直连。**Gmail 的 SMTP 在国内需要代理**才能连上,填 `socks5://127.0.0.1:7890` |
| 站点地址 | 邮件里链接的前缀。留空按访问者用的地址自动拼;用域名/反代访问时**建议填**,否则链接可能指向内网 IP |

填完点 **测试发送** —— 它会先保存当前填写的内容,再真的连一次 SMTP 发一封信,成功失败都给出具体原因
(连不上 / 认证失败 / 发件人被拒)。**先让测试发送成功,再开邮箱验证**,否则注册的人收不到信。

### 2. 开启「注册需要邮箱验证」

在 **设置 → 用户 → 注册与登录** 里勾选即可。行为:

- 注册表单多出**邮箱**字段(必填),账号先建好但**不能登录**;
- 系统发一封验证邮件,点里面的链接 → 跳到一个确认页 → 确认后即可登录;
- **老账号完全不受影响**:它们没有邮箱记录,不会因为开了这个开关被挡在门外 ——
  这是刻意的设计,否则一开开关就能把服务器主人自己锁在外面;
- 管理员手动建的账号同样不受影响;想让某人也能自己找回密码,让他到
  **右上角头像 → 账号设置 → 邮箱** 里绑定(或管理员在用户列表里代填,再点「标记已验证」);
- **没配 SMTP 就勾选这个开关**:注册会被明确拒绝(`503 管理员开启了邮箱验证,但服务器还没有配置邮件发送`),
  不会产生一个永远无法登录的账号;登录页也会说明原因。

### 3. 忘记密码(邮件重置)

登录页的 **忘记密码?** —— 填用户名或邮箱,系统发一封重置邮件:

- 链接 **1 小时**内有效、**只能用一次**;验证邮件是 24 小时;
- 重置成功后,**该账号所有设备都会被退出登录**(包括找回密码前还开着的页面);
- 用户不存在、或没绑邮箱、或已被禁用时,页面**给出完全相同的提示**且不发信 —— 避免被用来探测
  哪些账号存在;
- 跟着链接走完也**顺带证明了邮箱归属**,所以密码重置成功会同时把邮箱标记为已验证。

### 4. Cloudflare Turnstile(人机验证)

在 **设置 → 邮件与验证 → Cloudflare 人机验证** 里打开开关,填两把钥匙:

- **Site Key**(公开,给浏览器用)和 **Secret Key**(私密,服务端校验用),都填齐才会生效;
  只填一把等于没开 —— 这样打错字也不会把所有人挡在登录页外面;
- 生效范围:**登录页 + 注册页**。登录时**先验证人机、再校验密码**,所以脚本每猜一次密码都要先过一道验证;
- 免费。去 Cloudflare 后台 → Turnstile → 添加站点即可拿到两把钥匙。

> **两个务必知道的坑:**
>
> 1. **访客的浏览器必须能打开 `challenges.cloudflare.com`**,验证框才显示得出来。国内网络直连
>    通常打不开,需要在客户端侧有代理;打不开时登录页会明确提示「人机验证加载失败」并**禁用提交按钮**,
>    不会让你点了没反应。
> 2. **服务端连不上 Cloudflare 时,登录会被拒绝**(fail closed,不是放行)。如果因此谁都进不去:
>    编辑 `config.json`,把 `"turnstile": { "enabled": true }` 改成 `false`,重启服务即可 ——
>    这是留给你自己的后门。服务端校验请求可以走代理(同一个面板里填)。

### 安全细节(邮件相关)

- 验证/重置令牌是 32 字节随机数,一次性使用;**同一账号同一用途只保留最新一个**,
  所以点了「重新发送」之后旧邮件里的链接立即作废;
- 邮箱地址**不区分大小写**,同一个邮箱不能开两个账号;
- **发信限流**:同一 IP 每小时最多 5 封(找回密码 / 重新发送合计),
  免得这台服务器被人当成给别人发垃圾邮件的工具;
- SMTP 密码存在 `config.json` 里(和会话密钥同一个文件,那已经是这台服务器的信任边界),
  接口只在管理员请求 `GET /api/config` 时返回。

### 探测不再卡住起播(异步 + 预探测)

播放决策必须先探测源文件(容器/编码/音轨),而网盘文件探测很慢。所以:

- **`/api/play` 不再等探测**:没有缓存探测结果时,接口立即返回 `state=probing`
  (含标题与"正在探测媒体信息…"的原因),后台开始探测,前端轮询
  `/api/play/{id}/status`,就绪后再取一次决策。同一文件的探测是**单飞**的
  (多个页面/多次请求只探一次);失败会带原因返回,并冷却 30 秒避免反复打源。
- **探测窗口可配置**:默认 `probe_size_mb=8` + `probe_analyze_sec=4`(旧版固定 50MB/20s)。
  小窗口读不出来的文件会**自动用 50MB/20s 深度探测兜底**,所以不影响识别正确性。
- **扫描后后台预探测**:`preprobe_after_scan`(默认开)会在扫描结束后串行预热新文件的
  探测缓存(`preprobe_max_files` 限量、`preprobe_concurrency` 限并发),这样点开文件
  通常已经是 `ready`,直接出决策。

这几个开关都在 设置 → 刮削与播放 → 播放 里。

**关于「强制转封装」**:转封装只拷贝视频流,所以它只在**该客户端确实能解码这个视频编码**时才生效。
在 AV1 / VP9 / 10bit H.264 这类编码上硬拷只会得到**只有声音、没有画面**(视频流原样拷进去了,
客户端根本解不开),所以现在直接拒绝,并在播放页写明原因
(`手动指定转封装,但 AV1 无法被本机解码(只有声音没有画面);转码已禁用,无法播放`)。

**关于不转码**:视频重编码这个能力已经从决策里**整个移除**,不是默认关闭 —— 决策只会在
`302 直连 / 代理播放 / HLS 转封装 / 无法播放` 四者里选一个,`force=transcode` 也不再被接受
(老页面/bookmark 请求它,会落到自动决策)。因此:

- 设置里的「默认播放模式」没有转码选项了,「失败后允许自动改用转码」这个开关也一并删掉;
- 「转码最高高度」改名为**字幕烧录输出高度**:唯一还会重编码画面的地方是**烧录图形字幕**
  (PGS/VobSub 只能叠加),那里仍需限制输出高度;
- 本机解不了的编码(如 AV1、10bit H.264)会明确提示**无法播放**并给出原因,
  播放页只留「返回」,不再有重试/转码按钮;`internal/media/decision.go` 返回 `mode=unsupported`。

HLS 分片是**按需生成**的(每个片段请求时现场 `ffmpeg -ss`,转封装直拷),不写临时文件、
不预转整部片,seek 到哪生成到哪。播放 URL 都带 HMAC 签名,播放器无需带 Cookie。

### 字幕自动载入

字幕**不需要手动选**,打开就自动开。默认选哪一条由**服务端**决定(`/api/play` 里
`default_subtitle_id`,并在该条上标 `default:true`),规则是:中文优先 → 粤语 → 其他已知语言 →
无语言标记的;同语言内**简体优先于繁体**(两者 ISO 代码相同,只能靠标题区分,所以
`简日`/`繁体`/`chs`/`cht` 这类标记会被识别),再按文件内音轨顺序。内嵌字幕轨与同名字幕文件
都参与排序。

客户端拿到 `default` 后自动把该轨切到 `showing`;如果你想固定看某种语言,手动选一次即可,
选择会记在浏览器里(`dm:subPref`)并套用到后续文件。**手动关掉字幕也会被记住**——服务端标的
`default` 不会把它强行打开。

侧挂字幕按需转成 WebVTT,**ASS/SSA 的排版会尽量保留**;内嵌文本字幕轨先让 ffmpeg 转成 ASS
(它保留容器里的样式与定位,而 ffmpeg 自己的 WebVTT muxer 会把两者压平),再走同一条转换。
图形字幕(PGS/VobSub)无法转成文本,只能烧录,不会作为文本轨出现在列表里。

**字幕不再自带黑底**。浏览器画 WebVTT 的默认样式是「白字 + 黑框」,那块黑底正好糊在画面上,
所以全局样式里给 `video::cue` 换成了**透明底 + 描边**(`styles.css`),任何画面上都读得清,
又不挡画面;字幕文件自己要底框的(ASS `BorderStyle 3`)会以 `.dm-box` class 保留下来。

**ASS 转换保留什么**(`internal/media/subs.go`):

| 保留 | 形式 |
| --- | --- |
| 结束位置(`\an1`–`\an9`、样式 `Alignment`) | 顶部/中部/底部 + 左中右 → `line:` / `align:` |
| 定位(`\pos`、`\move` 起点) | 画面百分比 → `line:X%,start|center|end` |
| 粗体 / 斜体 / 下划线 / 删除线 | `<b> <i> <u>`,删除线走 `.dm-so` |
| 颜色(`\c`、样式 `PrimaryColour`、SRT 的 `<font color>`) | `::cue(.dm-cRRGGBB)` 的 STYLE 块 |
| 底框样式(`BorderStyle 3`) | `.dm-box` |
| 硬换行 `\N` / `\n`、`\h` | 真换行 / 不换行空格 |
| 卡拉OK `\k` | 唱词本身(丢掉逐字计时) |
| 文本里的 `&` `<` `>` 与未知标签 | 转义后原样显示,不会被当成标记吞掉 |

**刻意不保留**:像素级水平定位(WebVTT 的 cue 盒子是按宽度摆的,硬凑像素偏移只会把字挤出画面,
所以水平只分左/中/右)、字号(`\fs` ——会和播放器自己的缩放打架)、以及所有动画与矢量绘制
(`\t`、`\clip`、卡拉OK 扫词、`\p1` 图形——后者的「文字」其实是坐标,现在会被整条丢掉,而不是
把坐标糊到画面上)。

**底部位置**:所有原本没有定位的字幕都会被抬到画面底部上方(最底下那条的盒子顶边在 **88%**),
**并且堆叠由服务端自己算**,不再交给浏览器的碰撞处理 —— 交出去的话最底下那条会被放在画面最后一行,
也就是剧场控制栏底下。两个常量都是量出来的,不是猜的:

| 量到的东西 | 值 | 依据 |
| --- | --- | --- |
| 一行字幕占画面高度 | **7.25%** | 800px 高的画面里三条堆叠相距 58px;把画面缩到 400px 高时相距 29px,仍是 7.25% —— 跟的是**画面**而不是窗口 |
| 盒子重叠容差 | **1.5%** | 字形墨迹从盒子顶边往下约 1.6% 才开始、高 4.5%,所以 1.5% 以内的盒子重叠不可能压到字 |
| 底边基准 | **88%** | 按用户给的框定;Chrome 会**忽略 `line:X%,end` 的对齐分量**,按「盒子顶边在 X%」摆放,88% 就是按这种读法选的 |

堆叠规则:按时间顺序,每条字幕放在**它下面所有已放置字幕的最顶边之上**的最低空位(字幕盒子从给的那一行
向下生长,所以它上面那条只需要让开它的顶边,而它自己要给下面那条让出整段高度;换行的字幕因此占两行)。
文件自己用 `\pos` 钉在画面下部的牌子也计入避让 —— 但不会因为零点几个百分点的空隙就把对白顶到画面中部。

**百分比是相对「画面」的,不是相对「播放器元素」的。** 字幕的定位基准是元素盒子,而 `object-fit: contain`
会把画面letterbox 在元素里 —— 竖屏全屏放 16:9 的片子时,画面只是屏幕中间的一条,上下都是黑边。
这时按元素算出来的 88% 落在画面**下面的黑边里**,看着就是「字幕一直贴着最下方、离画面很远」。
所以播放器会把每条字幕的行位置**换算进画面自己的盒子**(ASS 的坐标本来就是视频空间的),
并且跟着元素尺寸变化重算(靠 `ResizeObserver`,因为 `fullscreenchange` 触发时元素往往还是旧尺寸)。
实测竖屏全屏(390×844,画面 312–532px):字幕盒子顶边落在 505px,相对画面仍是 88%。

**特效字幕想看原样就烧录**:ASS 轨在设置里额外给一个「忠实排版(烧录)」分组(标 `burn_available`),
点它会把字幕叠进画面并重编码(这是唯一还会重编码的路径,输出高度受「字幕烧录输出高度」限制)。
iOS 上这条尤其重要:iOS 用系统播放器渲染 HLS 里的 WebVTT 字幕轨,`line:`/`align:` 这类定位支持有限,
烧录是唯一能保证排版正确的方式。

## 界面(Web UI)

前端是 Vue3 + Vite 的单页应用,整体按流媒体网站的观感重做(参考 Netflix / Plex / MUBI 的暗色剧场风格):

- **全幅 Hero 剧场**:首页与详情页用背景大图 + 多层渐变遮罩,标题自动轮播、鼠标悬停暂停;
  背景有极缓的 ken-burns 位移,不会静止得像一张图。
- **横向影轨**:继续观看(带进度条与「还剩 x 分钟」)、最近添加的电影/剧集、评分最高的 Top 10
  (超大序号叠在封面上);影轨支持吸附滚动、悬停出现左右箭头。
- **海报卡**:悬停放大 + 信息浮层 + 快捷播放按钮;没有海报时用标题生成的渐变占位图,不留灰块。
- **顶栏与移动端**:顶栏在 Hero 上是透明渐变、滚动后变毛玻璃;`⌘/Ctrl + K` 呼出跨媒体库搜索面板;
  窄屏(<900px)自动切换为底部标签栏,并适配 iPhone 安全区。
- **播放页(三种形态,按设备自动选)**——都共用同一个 `<video>` 与同一条决策链路,
  `?view=phone|tablet|theater` 可以强制指定:
  - **桌面 / 手机横屏 = 全屏剧场**:自定义控制条(播放/暂停、±10s、音量、进度拖动与缓冲显示、
    **选集**、字幕、弹幕开关/设置、倍速、画中画、全屏、快捷键 `空格/←→/J K/↑↓/M/F/P/D/0-9`),
    右侧抽屉切换版本/音轨/播放速度/播放模式;选集在字幕按钮左边,点开是本季的列表(当前集高亮
    并自动滚到可见处),点一集直接换过去,不用离开画面。画面顶部那条只剩「返回 + 标题」——
    原来那颗设置按钮和底部的齿轮重复,已经去掉;抽屉仍在,入口收到齿轮菜单的「全部播放设置」里。
  - **手机竖屏 = 竖屏观看页**(YouTube / Bilibili 那种):视频 16:9 在顶部,控制条紧贴视频下方,
    再往下是标题与元信息、**上一集 / 下一集**、`选集 / 简介 / 设置` 三个标签页——选集是数字网格
    (当前集高亮),设置是内嵌的音轨/字幕/倍速/播放模式;点选集会自动滚回顶部,
    转成横屏立刻变回全屏剧场且播放不中断;字幕分组用换行横排的 chip,和倍速一个形状,
    ASS 轨再多一个「忠实排版(烧录)」分组;
  - **iPad / 平板**:视频在左上角、控制条在视频下面,**选集做成右侧侧栏**(带剧照、当前集高亮、
    剧集标题与播出日期),标签页只剩 `简介 / 设置`;电影之类没有剧集的条目则收起侧栏、视频居中。
    平板的**画面上不放任何按钮**——iPadOS 自己的全屏键就在视频左上角,再压一个返回键必然误触,
    所以 `返回` 放在视频下方的文字区里;进全屏之后画面上才恢复「返回 + 标题」这一条。
  - **加载状态**:观看页(手机竖屏 / 平板)把「正在探测媒体信息 / 正在生成分片 / 正在缓冲」做成
    视频下方的**长条进度条 + 一行文字**——不放在画面正中,免得同时盖住画面和中间那颗播放按钮;
    能拿到分片进度时显示真实百分比,还没测到时走循环扫光。全屏剧场没有"下方"可用,仍是画面
    中央的转圈 + 提示卡。
  - **什么时候算"在加载"由播放进度说了算**:只要播放位置在往前走,加载状态立刻消失并且不再回来。
    `waiting` 事件不是证据(元素在预缓冲时也会发),**`readyState` 更不是** —— 弱网下
    画面明明在动,`readyState` 却可以整部片停在 `HAVE_CURRENT_DATA`(2),因为数据是一片一片
    到的。所以判定只看播放位置:它停住(或用户暂停)才显示加载,任何一个 `timeupdate` 推进
    就清掉;`canplay`(数据够继续播)也会清一次,这样暂停在缓冲中的观众不会被一直挂着。
    这样既不会出现"片子已经在放了,圈还在转",也不会因为圈转久了就弹出「要不要转封装」
    —— 那个提示只在画面真的卡住 25 秒后才出现。
  - 选集列表来自 `条目 → 季 → 该季全部剧集`,三种形态都会去拉(剧场要靠它填控制条上的选集);
    剧集之间切换用 `router.replace`,所以返回键仍然是回到季页面而不是逐集后退。
  - iOS 无论哪种形态都用**原生播放控件**以保证兼容性;准备阶段显示**分片生成进度条**与
    **编码速度 x× 实时**。
- **播放手势**:触摸设备上**单击画面不暂停**(手搭在屏幕上太容易误触),单击只把控制条唤回来,
  暂停/播放要点**双击**(自己数 240ms 内的两下,不用浏览器的 dblclick——它的判定窗口太宽,
  会把两次不相干的点击算成双击);桌面端保持「单击暂停 / 双击全屏」。iOS 交给原生控件。
  播放器**自己没有任何滑动手势**;全屏时它会消费(对非弹窗目标 `preventDefault`,并关掉
  `overscroll-behavior`)那些没人处理的拖动,免得变成浏览器的手势 —— 手机上向下拖是下拉刷新,
  会整页重载并从上次进度继续,看起来就像「莫名其妙倒退了几秒」。
- **关于浏览器自带的视频手势**:部分安卓浏览器(以及三星浏览器)在全屏视频上自己带一层手势:
  左右滑快进/快退、右侧上下滑调音量、左侧上下滑调**亮度**。最后一条是关键证据 —— **网页没有任何 API
  能改屏幕亮度**,所以那层手势属于浏览器,网页拿不到也拦不住(只能靠消费触摸尽量少触发)。
  想确认是不是它,换个浏览器(或关掉浏览器设置里的「视频助手 / 手势」)再试同一段操作即可。
- **全屏里的设置栏**:全屏时设置是**右侧一条栏**(手机上 `min(340px, 86vw)`),不是整屏的抽屉——画面还在后面,
  读起来是「一个面板」而不是「换了一页」;其中字号、芯片内边距、间距都按窗口高度 `clamp()`,保证**不用上下翻动**
  就能点到所有按钮(实测 844×390 与 390×844 两种尺寸下 `scrollHeight` 恰好等于 `clientHeight`,溢出 0px)。
- **一条栏,两个面**:字幕按钮(字幕)和齿轮(播放设置)以前调的是同一个开关,所以全屏里点「字幕」得到的是
  整张设置表。现在这张栏有两个面 —— 点「字幕」只出**字幕**(字幕轨 + 忠实排版(烧录)),点齿轮出**其余设置**
  (版本 / 音轨 / 播放速度 / 播放模式 / 画面);标题跟着换。看片页(非全屏)仍是一页里全都在,顺序不变。
  这也顺带是手势修复:设置列表一旦要滚动,手指在划的过程中就更容易滑到音量上。窗口特别矮(≤520px)时,
  列表末尾那条说明会收起来(同样的信息有 toast),`overflow-y: auto` 仍作为极端多音轨时的兜底。
- **全屏**:进的是**整个播放器**,不是画面那一个元素。全屏是一层顶层(top layer),只渲染全屏元素自己的
  子树,所以把画面单独拿去全屏时,设置抽屉在顶层之外 —— 既不在屏幕上,也收不到触摸,拖动会穿透到画面上的
  控制条(实测:往设置列表里上下拖,落点是音量滑杆;锁定后横向拖,落点是隐藏的进度条)。现在整机上全屏,
  链条靠 CSS 铺满,页面自身的标题/选集/标签页在全屏下让位,设置抽屉作为右侧浮层正常工作。
- **全屏锁定**:进入全屏后画面**左侧正中**有一个锁按钮,点一下锁定——顶部返回、控制条、进度条、
  快捷键提示全部隐藏,**并且不再是可点中的元素**(看不见的控件不能还是控件),画面本身也不再响应拖动
  (`touch-action: none`),弹窗直接不渲染;再点一下解锁;退出全屏自动解锁。桌面端键盘快捷键不受锁定影响,
  `Esc` 始终能退出全屏。
- **细节**:骨架屏、图片渐入、Toast、空状态、焦点环、`prefers-reduced-motion` 降级、列表/网格视图切换。

设计 token 集中在 `webui/src/styles.css`,组件在 `webui/src/components/`。

## 自己改站点的样子(编辑工具栏)

登录后打开 <http://127.0.0.1:5666/login?toolbar=1>(或者 **设置 → 站点外观 → 改登录页文案**,
登录页右下角也有一个「编辑此页」小按钮),页面右下角会出现一条浮动工具栏——和 Vercel 部署后的
"Visit with toolbar" 同一个用法:**页面本身就是编辑器**,改完立刻能看到样子。

- **文案**:标题、段落、亮点卡片、按钮文字、链接文字、登录表单的四种状态说明、页脚每一栏,
  都能直接**在页面上点着改**(点进那一行就变成可输入的文本,`{host}` 这类占位符在点进去时才显示);
  右边的面板既可以改同一批文案,也可以增删/排序亮点卡片与页脚栏目。
- **布局**:品牌面板在左还是右、两栏比例、表单宽度、圆角、背景渐变与网格的开关与浓淡、
  亮点卡片单/双列、主题色(琥珀/蓝/紫/绿/粉——只作用于登录页与页脚,不动后台其他页面)。
- **页脚**:品牌名、简介、运行状态、链接栏目(带路由候选)、播放能力、版权行。
  页脚只出现在登录后的页面上,所以在登录页打开「页脚」时面板会说明这一点,并给一个
  「改登录页底部那行小字」的入口。
- **不会改瞎**:所有改动先是浏览器里的草稿,只有点**发布**(或 `Ctrl/Cmd + S`)才对访客生效;
  `Ctrl/Cmd + Z` 撤销、`Esc` 收起面板、眼睛图标关掉虚线标记只看效果。
  标题栏会显示「有未发布的修改」,面板底部写着上次发布的时间与操作者。
- **占位符**:`{host}` / `{version}` / `{site}` / `{year}` / `{user}`,发布后按当前访问者填充。
- **两个窗口同时改**:发布时会带上加载时的版本号,落后者收到 409,提示「有人在这期间改过」
  并自动拉取最新版本,不会把别人的改动覆盖掉。
- **恢复内置文案**:面板底部的刷新按钮(`恢复成内置文案`)清空所有已发布内容。

内容存在 `data/site.json`(随数据目录),形如 `{"revision":2,"updated_at":"…","updated_by":"admin","content":{…}}`;
`content` 为空就表示"从没发布过",前端回落到代码里内置的默认文案。服务端不校验结构,
字段的增删只发生在前端(`webui/src/site/schema.js`),所以加一条可改的文案不需要动后端。

## 开发

```
webui\        Vue3 + Vite 前端(pnpm dev 热更新,代理 /api → 5666)
  src/components/  顶栏、影轨、海报卡、Hero、搜索面板、Toast、图标…
  src/views/       首页 / 媒体库 / 详情 / 季集 / 文件 / 播放 / 设置 / 登录
cmd\doriyamedia\   服务端入口
cmd\mockopenlist\  OpenList v3 API 的本地 mock(测试 302 链路用)
scripts\e2e-test.ps1   端到端冒烟测试(先启动 doriyamedia + mockopenlist + testdata)
scripts\browse-live-test.ps1   对真实 OpenList 跑浏览→决策→302/转封装链路
testdata\     ffmpeg 生成的测试片源(h264/hvc1/hev1/mkv-eac3/剧集+字幕)
```

调试前端:`pnpm dev`(端口 5166)+ 后端 `.\doriyamedia.exe`,浏览器开 http://127.0.0.1:5166。
也可以给后端配置 `dev_web_dir`(例如 `internal/web/dist`),这样改完前端只需 `pnpm build`、不用重启后端。

改完前端记得 `pnpm build`:页面是**嵌进二进制**的(`internal/web/dist`),不 build 的话 `go build` 出来的
还是旧界面。编辑工具栏的回归脚本在 `.uitest/verify.mjs`(需要先起后端,并用
`chrome --headless=new --remote-debugging-port=9333` 开一个 Chrome),它会把工具栏点一遍并截图。

## 已知限制 / Roadmap

- [ ] iOS Safari 原生 HLS 播放时,外挂 VTT 字幕的 `<track>` 支持不稳定(建议用内嵌文字字幕,或等 HLS 字幕轨方案);
- [ ] PGS/图形字幕只能烧录(会重编码画面),暂不支持外挂;
- [x] 不再转码:解不了的编码直接提示无法播放,只保留 302 / 代理 / HLS 转封装;
- [ ] 多音轨在 302 直连模式下由浏览器选择(通常第一条),HLS 模式下可切换;
- [ ] 剧集季/集刮削依赖 Show 已匹配 TMDB;手动指定 TMDB ID 在详情页"重新识别"里;
- [x] 多用户:开放注册(可切审核/关闭)、后台仅管理员可进、管理员用户管理;
- [x] B 站正版番剧源:虚拟目录浏览、**可建媒体库**(扫描/海报/续播)、服务端双流合流播放、弹幕;
- [x] B 站番剧按 B 站自己的「系列 → 季度」合并成一部剧多季(系列/季度目录里带 id,无状态);
- [x] B 站源「只上架当前线路能播放的番剧」:港澳台代理自动跳过大陆限定,大陆代理反之(可按源关闭);
- [x] 港澳台繁体标题的刮削兼容(搜索与比对折叠为简体),以及 B 站来源角标;
- [x] 弹幕设置按 B 站那套做全:显示区域(1/4·半屏·3/4·全屏)、不透明度、字号、速度、类型开关、恢复默认;
- [x] 媒体库可挂多个存储源,分别扫描并合并(移除某个源只删它自己的条目);
- [x] B 站源扫码登录:设置页出二维码、手机一扫即登录,拿到属于服务器自己的会话 + `refresh_token`,
      可自动/手动续期;账号状态(登录人、大会员到期、Cookie 是否失效)直接显示在存储源卡片上;
- [ ] B 站源还没做的:普通投稿视频与合集、
      「只代理不封装」的低清省 CPU 模式(`platform=html5` 单文件,已验证可行)、
      独立的番剧页(搜索 / 按年份分类,目前用「文件」浏览器或媒体库);
- [ ] 按用户分配可见媒体库(目前所有用户共享全部媒体库)、播放队列、WebDAV 直链透传、
      天翼云盘原生驱动(免 OpenList)在计划中。
